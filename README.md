# OWASP CRS 보안 수준별 차단과 오탐 비교

박지훈의 과제 10 정보보안 실험입니다. 실제 Nginx에 연결된 ModSecurity와 CRS 4.0.0에서 정상 입력 60개와 공격 특징 입력 60개를 PL1·PL2·PL3 및 HTTP·HTTPS로 각각 10회 전송했습니다.

**이 저장소의 로그는 공개를 위해 주소와 서버 식별정보를 처리한 파생 자료입니다. 제출용 원본 ZIP과 바이트가 같지 않습니다. 실제 서버 접속 주소는 제공하지 않습니다.**

## 결과

각 접속 방식에서의 결과입니다. HTTP와 HTTPS는 입력별 응답도 일치했습니다.

| PL | 정상 입력 오탐률 | 공격 특징 입력 차단율 |
|---|---:|---:|
| PL1 | 20.00% | 98.33% |
| PL2 | 66.67% | 98.33% |
| PL3 | 100.00% | 98.33% |

![실험 결과](results_chart.png)

공격 특징 입력 60개 중 `1 OR TRUE` 한 종류가 모든 조건에서 허용됐습니다. 실제 DB·취약 WAS 또는 XSS 실행은 포함하지 않았으므로 공격 성공률을 측정한 결과가 아닙니다. 정상 입력은 코드 설명을 문자로 허용하는 업무 정책을 기준으로 정했습니다. 기본 사례와 접두 문장을 공유하는 입력과 반복 전송을 독립 표본으로 간주하지 않습니다.

## 파일 읽는 순서

1. `T10_WAF_Paper.md` 또는 `T10_WAF_Paper.docx`: 원 실험 논문. 논문의 원자료 무결성 설명은 비공개 제출 원본에 대한 당시 검증입니다.
2. `PUBLICATION_REVIEW.md`: 공개 전 점검 결과와 어떤 정보를 제외했는지.
3. `README_REPRODUCTION.md`: 결과 재검증 및 별도 Ubuntu 서버 재실행 방법.
4. `original/results/20261020T005958Z-ca99f72b/`: 주소 처리한 응답·감사 로그·집계 CSV. `original`은 원래 패키지 구조를 유지한 폴더명이며 공개 사본이 무가공 원본이라는 의미는 아닙니다.
5. `PUBLIC_DATA_TRANSFORMATIONS.json`: 처리 내역과 원 제출 ZIP의 해시.

## 서버 없이 결과 검증

Python 3 표준 라이브러리만 사용합니다. ZIP을 압축 해제하거나 저장소를 clone한 뒤 루트 폴더에서 실행합니다.

```
python analysis/independent_verify.py original verification-output
```

예상: 요청 7,200건, WAF 대응 7,200건, HTTP/HTTPS 대응 3,600쌍, 응답 차이 0, issues 빈 목록, passed true. 공개본에는 인증서가 없으므로 `certificate_verified`는 false이며 이는 인증서 검증을 수행하지 않았다는 명시적 표시입니다. 현재 공개 원자료 목록 해시는 30개입니다. 기존 제출 원본의 해시 목록 78개와 구분합니다.

## 공개 과정에서 한 일

- 실제 현재·과거 공인 IP는 예시 주소 `203.0.113.10`으로 치환했습니다. 이 주소는 접속용이 아닙니다.
- 내부 호스트명과 ModSecurity 서버 식별 문자열을 대체했습니다.
- 감사 로그에서 본 실험과 무관한 사전·브라우저 테스트 37건을 제외하고 본 실험 7,200건만 남겼습니다.
- 실제 IP를 담은 자체 서명 공개 인증서를 제외했습니다. 원래부터 개인키는 패키지에 없었습니다.
- 원문 규칙 파일 묶음 대신 CRS 4.0.0 공식 다운로드와 파일별 해시 검증 코드를 제공합니다. 회귀 테스트용 공격 fixture는 가져오지 않습니다.
- 주소 변경 후 실행기·원자료 해시를 재산출했습니다. 원 인증서 해시는 출처 기록용으로만 남겼고 검증 성공으로 표시하지 않았습니다.
- 입력 문자열, 정상·공격 레이블, PL, 프로토콜, 회차, 응답 상태와 요청 건수는 원본과 비교해 변하지 않았음을 확인했습니다.

작성자 이름은 논문 저자 표시로 유지했습니다. 이름까지 익명화한 자료가 아닙니다. 상세 파일별 검증은 `verification/independent-verification.json`에 있습니다.

## 새 서버 재실행

별도의 Ubuntu 24.04 amd64 실험 VM에서만 설치 스크립트를 사용합니다. 현재 저장소를 모두 다운로드한 뒤 실행합니다.

```
bash reproduction/bootstrap_ubuntu.sh 현재_EC2_공인IPv4
python3 ~/t10-waf/run_main.py --rounds 10
```

설치기는 먼저 공식 CRS 4.0.0의 필요한 파일만 받아 제공된 SHA256과 비교합니다. 새 서버 인증서와 개인키는 해당 서버에서 새로 생성합니다. 이 설치 스크립트는 구문·파일 구성을 점검했지만 이 공개 검토 과정에서 새 EC2를 생성해 실행한 것은 아닙니다. 원 서버 HTML 대신 별도 재현 페이지를 제공합니다. apt 현재 버전이 바뀌면 기준 환경과 구분해 기록합니다.

- 공개 저장소는 읽고 내려받을 수 있다는 뜻입니다. 작성자 자료에 별도의 오픈소스 라이선스를 자동 부여한 것은 아닙니다. 원자료·논문 인용 시 저자와 실험 범위를 표시하십시오.

실제 운영 서버 접속 정보, SSH 키, 서버 인증서 개인키, 환경변수 비밀 파일을 추가 업로드하지 마십시오.
